# SPU直結からPIOデバッグ基板へ移行する計画

[English](direct-to-pio-plan.en.md) / [README](../README.md) / [PIO方式の設計検討](parallel-io-dongle.md)

更新日：2026-09-04。日本語を正本とする。実機作業の順序と成果物を定める計画であり、未確認のはんだ箇所を施工指示として指定するものではない。

## 最初に何を作るか

**最初はPIOの信号を一切使わず、SPU直結でS/PDIF出力を完成させる。その後、PIOデバッグ基板へ接続経路を移す。**

FPGAは既存PoCのTang Nano 9Kを初期基準とする。他機種を使う場合はその段階で端子・電源・資源を再照合する。動作中のクロック切り替え回路は初期範囲に含めない。

「LUT構築」は、RTLを合成し、FPGA内部のLUT・レジスタ等へ配置配線してビットストリームを作る工程として扱う。基本処理を共有し、直結版とPIO版のビットストリームを別々に生成する。配線だけを変更して同じ書込みデータを使えるとは仮定しない。

## 現在の実装と本計画の位置付け

| 所在 | 状態 |
|---|---|
| 本リポジトリのPoC | SPU直結用PCM受信・FIFO・S/PDIF送信RTL、9Kの直結ピン設定あり。384Fsを想定。実機未検証 |
| `ps1-pio-lab-pcb` | PIO全68接点の測定基板と、少数入力のFPGAアダプター、光出力基板の設計候補 |
| 同PCBリポジトリの`feat/pio-spdif-integration`、`793d647` | PoC由来RTLを修正し、3/6周期更新、基板ピン設定、PCM→S/PDIF復号テストを追加した別ブランチ |

計画追加時点では統合版の共通修正は未反映だったが、現在の修正ブランチではFIFO満杯判定、音声ビット配置、左右ペア処理、受信開始とリセット処理を反映した。[反映範囲と検証結果](rtl-backport.md)を参照。直結384Fsの8条件を復号検証済み。PIO用6周期設定・基板固有機能は持ち込んでいない。実機検証は未完了。

統合版での16条件と基板トップ2条件のシミュレーション成功は論理上の検証。電圧、実クロック、ジッタ、配線、Gowin配置配線、光受信ロックを保証しない。

## 第1段階：PIOを使わないSPU直結

```text
PS1内部SPU：WCKO / BCKO / LRCO / DATO
              │ 内部から取り出す配線＋GND
              ▼
      必要なバッファ・電圧整合
              ▼
         Tang Nano 9K
              ▼
       PLT133/T10W → 光受信機
```

| 順序 | 作業 | 成果物・完了条件 |
|---|---|---|
| 1 | 対象PS1の基板版・IC・既存改造を確認 | 取り出し点候補と番号視点を記録 |
| 2 | 配線前にGND、電圧、クロック、PCMを測定 | 波形と測定表。未確認はTBDのまま |
| 3 | 取り出し点と保護回路を確定 | 写真/図で示す手はんだ手順、導通表、部品・配線表 |
| 4 | 電源OFFで配線し、通電前検査 | 短絡なし、各経路とGNDの導通一致 |
| 5 | 保護回路後のFPGA側でも波形確認 | 受信エッジ、左右極性、スロット長、入力遅延を確定 |
| 6 | 修正RTLを直結条件に適合させる | 直結CST、SDC、パラメータ、既知PCM復号テスト |
| 7 | 合成・配置配線・タイミング確認後に書込み | SPU直結版ビットストリームと対応する配線表 |
| 8 | 光出力を検証 | 左右別の既知PCM、起動/reset、無音、長時間、FIFO異常を確認 |

WCKOが16.9344MHzで44.1kHzと同期するなら384Fs。S/PDIFのBMC半ビット更新は3周期ごととする。実測前に周波数・極性・タイミングを固定しない。

### 手はんだ手順の作り方

現時点で確定するのは作業の順序。実際のはんだ箇所は対象基板を確認してから図示する。

1. 対象基板の部品番号・向き・接点を特定し、ICの足以外のパッド等で取り出せるか確認する。READMEのIC端子番号は候補として照合する。
2. 電源OFF・電源接続を外した状態で、対象基板向けの手順に従って分解する。電源基板は作業対象にしない。
3. 確定した4信号とdigital GNDを、指定した取り出し点から外部接続先へ配線する。線材・長さ・固定・ケースからの引出し方は現物に合わせて決める。
4. 拡大確認でブリッジ、隣接端子接触、線への張力を確認し、配線表に従い導通と短絡を検査する。
5. FPGAへの接続前に電気条件を確認し、接続後にも負荷・リンギングを再測定する。

基板未確認の段階で「この足へはんだ付け」と断定した図や、電源ONのまま配線する手順は作らない。直結段階ではPIO空き端子への追加配線は不要。

## 第2段階：PIOデバッグ基板への移行

```text
SPU → 必要な信号をPIOの空き端子へ内部配線
                         ▼
PIO → デバッグ基板 → FPGAアダプター → Tang Nano 9K → 同じ光出力
```

直結で得たPCM条件と試験データを基準に、次の案を比較する。先に768Fsを必須と決めない。

| 案 | 信号経路 | FPGA側 | 未確認事項 |
|---|---|---|---|
| A：現行PCB案を利用 | DATOをPIO31へ追加する候補。PIO32 SYSCLK1、PIO33 BCLK、PIO66 LRCLKを利用 | SYSCLK1が768Fsなら6周期更新 | 追加DATOとPIO音声クロックの整合、長時間同期 |
| B：WCKOも引き出す | 音声データに加えSPU WCKOを空き端子へ追加する候補 | WCKOが384Fsなら3周期更新。アダプターに受信経路追加が必要 | 空き端子、クロック入力、BCLK/LRCLKとの整合 |

PIO65をWCKO用に使えるかは改造・導通確認後に決める。現行アダプターにはPIO65→FPGAの受信経路がない。WCKOを追加してもPIO BCLK/LRCLKが使える証明にはならず、合わなければ追加配線や基板構成を再検討する。

PIOコネクタは信号の通り道であり、経由するだけで384Fsが768Fsへ変換されることはない。クロックを一つに固定し、専用ビットストリームを使えば動的切り替え回路は不要。信号源の出力同士を短絡しない。

### 移行時の作業順序

1. PIO/IDC/アダプターの全経路、端子方向、電源、既存改造を確認する。PSIO等による31/65の転用を無視しない。
2. 案A/Bを選び、内部配線・アダプター変更・抵抗実装を一枚の接続表へまとめる。
3. 元の直結配線を残す/外す範囲と負荷を決め、電源OFFで施工する。異なるクロック源を同じ入力へ同時接続しない。
4. 現行案ではPIO31経路のR4はDNP。音声経路と電圧を確認してから実装する。実装だけで音声が得られるとは扱わない。
5. 既存JP1はOPENで起動し、FPGA入力設定後に受信を有効化。再書込み前にOPENへ戻す。JP1は自動保護でも入力負荷の切断でもない。
6. FPGA側でクロック・PCMを再測定。直結時の遅延値を長いPIO経路へ流用しない。
7. PIO版のCST・SDC・更新周期を確定し、シミュレーションと配置配線後にPIO版ビットストリームを生成する。
8. 直結時と同じPCMで復号結果・左右・安定性を比較する。直結成功をPIO成功の代わりにしない。

## 段階ごとに残す成果物

| 成果物 | SPU直結版 | PIO版 |
|---|---|---|
| 配線・手はんだ資料 | 取り出し点→保護→FPGA | 内部→PIO→IDC→アダプター→FPGA |
| 測定記録 | SPUとFPGA側の波形 | PIOとFPGA側の波形 |
| FPGA設定 | 直結端子、384Fs等の実測条件 | PIO端子、選択した384/768Fs等の実測条件 |
| 書込みデータ | 直結版、ソースrevisionを記録 | PIO版、ソースrevisionを記録 |
| 動作記録 | PCM復号・光出力 | 直結版との一致・長時間動作 |

測定表には各信号の取り出し点、電圧範囲、周波数、信号方向、FPGA端子、受信エッジ、LRCLK極性、スロット長、setup/hold、追加部品・配線長を記録する。公開資料では個人情報・端末情報を含めない。

## 次に行う作業

SPU直結版を優先する。共通RTL修正と論理検証は本ブランチで実施した。対象PS1の基板確認、取り出し点の図示、実測表、直結CST/SDCの確定、配置配線とビットストリーム生成手順は引き続き必要。PIOへの内部配線と基板改訂は、その結果を見て進める。
