# 直結PoCのタイミング制約と波形検証

[English](timing-validation.en.md) / [README](../README.md)

日本語を正本とする。SDCは未測定テンプレートであり、実機用の制約完成・タイミング収束を意味しない。
クロック周期を記入するだけでは、入力やクロックドメイン間の経路を検証できない。

## 測定して埋める値

オシロスコープで、バッファ・ケーブルを含む最終経路のFPGA入力側を測定する。
開発時の使用機種はDHO914S。接続前の電圧確認はREADMEに従う。

| 項目 | 現状 | 制約への反映 |
|---|---|---|
| WCKO周期・最短周期・デューティ比・変動 | ConsoleMods表記MCLKで16.806 MHzを撮影、直前に16.949 MHzも観測。WCKO同一性、384 Fs、最短周期・duty・変動はTBD | `create_clock`、必要なら`-waveform`、クロック余裕 |
| BCKO周期・最短周期・デューティ比・変動 | 2.8225 MHzを実測。最短周期・duty・変動はTBD | `create_clock`、必要なら`-waveform`、クロック余裕 |
| DATOの送出基準エッジ、最早/最遅到着時刻 | 音楽再生中の単一取得ではBCKO立下り付近でDATO遷移を観測。立上りcaptureが第一候補。probe間skewと正確なsetup/holdはTBD | BCKO基準の`set_input_delay -min/-max` |
| LRCOの周波数、送出基準エッジ、最早/最遅到着時刻 | 44.097 kHzを実測。edge/timingはTBD | DATOとは別に`set_input_delay -min/-max` |
| LRCO極性、スロット境界、受信エッジ | TBD | topのパラメータ、テスト入力、STAの捕捉エッジ |
| WCKO/BCKOの周波数比・位相関係・停止/再開 | MCLK/BCKO比は最新値で約5.954、直前値で約6.005。正確な比・位相・同期・停止/再開はTBD | クロック間関係のモデル、連続運転試験 |

最早/最遅値には信号とクロックの配線差、バッファ遅延、測定誤差、変動の余裕を含める。
`-clock_fall`は入力遅延の基準を立下りにする指定であり、RTLの受信エッジ選択とは別。
負エッジ受信時は合成後の反転クロックが正しく認識されていることも確認する。
測定した典型波形だけを全動作条件の保証値としない。

2026-09-06にSCPH-7000 / PU-20のConsoleMods表記LRCK/BCK/MCLK取り出し点をDHO914Sで測定し、
LRCO 44.097 kHz、BCKO 2.8225 MHz、LRCO/BCKO比約64.01を観測した。MCLKは掲載写真で
16.806 MHz、その直前に16.949 MHzを表示したため、約16.8～16.95 MHzのクロック候補として扱い、
公称16.9344 MHz、384 Fs、BCKOとの正確な6:1関係はまだ確定しない。詳細条件と写真は
[READMEの実機測定記録](../README.md#lrco--bcko--dato--mclk測定のエビデンス2026-09-06)を参照する。
LRCO/BCKOの周波数と64 Fs関係は確認済みとするが、長いワニ口ground leadで観測したpeak電圧を
FPGA端子の保証値や直結可否には使用しない。

同日の音楽CD再生中の単一取得では、DATOがBCKO立下り付近で遷移し、立上り付近で安定して見えた。
したがって現時点のRTL候補はBCKO立上りcaptureとする。ただし、長いground lead、probe間skew、
取得例の少なさが残るため、正確なsetup/hold、capture edge、slot境界、Right-Justifiedのbit位置は
引き続きTBDとする。

## FIFO・resetのクロックドメイン間確認

以下はRTL内の論理名。Gowin合成後のノード名・ビット数はNetlistで照合する。
対象なしの制約、想定外のワイルドカード一致を受け入れない。

| 経路 | 確認内容 |
|---|---|
| `fifo.wr_gray` → `fifo.wr_gray_r1` | RX→TXのGrayポインタ全ビットの実配線遅延とスキュー |
| `fifo.rd_gray` → `fifo.rd_gray_w1` | TX→RXのGrayポインタ全ビットの実配線遅延とスキュー |
| 各第1同期段 → 第2同期段 | 同じ宛先クロックでsetup/holdを解析し、同期段を維持・近接配置できているか |
| FIFO `mem` → TXの`frame_q`/`word_q` | メモリ推論結果、データが読出し許可に先行して安定する余裕、実データ経路の遅延 |
| `reset_release`と各ドメインのreset | 2段同期解除の維持、recovery/removal、POR・遅れて開始するクロック |

Grayポインタは論理上1ビットずつ変化するが、配線遅延差により異なる更新が重なる可能性がある。
送信元の最短クロック周期を基準に余裕を引いた遅延予算を決め、両方向の全ビットを確認する。
SDCの`set_max_delay`例は構文の雛形であり、それだけで実配線スキューを保証するものではない。
Gowinのレポートに含まれるクロック遅延の扱いも確認し、実データパスの遅延を検査する。

クロック全体を一括で`set_false_path`や非同期`set_clock_groups`へ指定して完了にしない。
必要な例外は対象を限定し、Gray経路の遅延制約を無効にしていないことを例外レポートで確認する。
別ツールの`-datapath_only`や`ASYNC_REG`属性がGowinで同じ意味を持つとは仮定しない。
同期段の保持・配置方法は採用するGowin版の文書と合成結果で確定する。

## 実機用ビットストリームを作る前に

1. 実測値と余裕の根拠を記録し、SDCのTBDとtop設定を確定する。
2. 合成後、WCKO/BCKOのクロック配線資源を確認する。CSTの端子25/26は一般I/Oであり、端子番号・電圧の照合だけではクロック配線の成立を保証しない。
3. LED端子15/16は公式回路図のBank 3（1.8 V）に合わせて`LVCMOS18`を明示する。
4. 配置配線後、クロック一覧、入力setup/hold、上記CDC経路、reset、例外適用対象を確認する。最大周波数だけで合格にしない。
5. S/PDIF出力には相手側の同期クロック端子がない。架空の`set_output_delay`値を置かず、出力波形・パルス幅・光送信器との相互運用性を実測する。LED等の非同期出力も解析範囲と除外理由を記録する。
6. EDA版、ソースcommit、対象基板、測定条件、制約、配置配線レポートを対応付ける。起動・reset・長時間動作も実機で検証する。

Gowin合成・配置配線と実機検証は未完了。未測定項目を埋めずに実機試験へ進めない。

## シミュレーションで保証する範囲

`make test`は8条件のPCM復号に加え、記録した各TXクロック周期で、半ビット中の出力保持を検査する。
最初の遷移から半ビット境界を求め、起動待ち時間に依存した間引きをしない。
各半ビットの後続2周期をそれぞれ壊した波形が失敗すること、起動待ち時間を変えても正常波形を受け入れることを検証する。
これはクロック周期単位の論理試験であり、クロックより短いグリッチ、メタステーブル、実配線遅延の検証ではない。

44.1kHzの場合、半ビットレートは5.6448MHz、半ビット幅は約177.15ns。
BMCの実際の遷移回数はデータとプリアンブルに依存し、常に毎秒5.6448M回ではない。
