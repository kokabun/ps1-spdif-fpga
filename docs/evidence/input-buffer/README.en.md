# Public evidence for standalone input-buffer tests

[日本語・正本](README.md) / [Measurement procedure](../../input-buffer-measurement.en.md) / [Test overview](../../input-buffer-test.en.md)

This tracked folder contains **publication-reviewed material only**. No real results have been registered. Procedure/mock-test success is not hardware-test success.

## Layout

Create one folder per run, such as `ibuf-001/`, containing selected material:

- `README.md`: authoritative Japanese results, conditions, reasoning and remaining unknowns.
- `README.en.md`: translation when available, with reciprocal language links.
- `enabled.png` / `disabled.png`: reviewed scope screens.
- Setup photographs or waveform excerpts only when needed and authorized.

Originals/working analyses belong in [local storage](../../../captures/input-buffer/README.en.md). Existing PU-20 evidence is not moved or replaced.

## Before registration

- [ ] Identify the run, circuit/FPGA/tool versions, conditions and test points.
- [ ] Distinguish confirmed, needs remeasurement and unperformed; standalone success does not authorize PS1 connection.
- [ ] Inspect images/metadata, CSV, JSON, analysis text, comments and filenames.
- [ ] Exclude IPs, serials, personal information, absolute paths and private notes.
- [ ] Obtain user authorization for the selected content and disclosure scope.
- [ ] Select only necessary files and inspect diff/size.

Raw ZIPs/full CSVs are not included by default. If added, inspect every member. Commit/push approval is separate from measurement.
